# MAJIN V3 upstream research

**Research date:** 2026-10-22. Candidate status and licenses are recorded from project repositories/docs as currently observed; re-check the exact selected release and transitive dependencies before a production integration. Stars are not used as a selection rule. No upstream source was copied into V3 in this round.

## Repository-native options first

The highest-value reuse is already in MAJINCLI: V2 has durable goals, receipts, verification, DAG scheduling, model profiles, recovery, memory/context and safe-exec contracts. V1 contains browser grounding/evidence/recovery and desktop/file/provider tools. The V3 file slice adopts V2's Goal + file verifier and composes them without duplicating their behavior. V2's existing orchestrator contains deterministic templates, so its presence is not evidence of a general-purpose autonomous builder.

## External candidates

| Project | License / maintenance evidence | Technical fit, Windows, dependencies, security/performance | Decision |
|---|---|---|---|
| [Microsoft Playwright](https://github.com/microsoft/playwright) | Apache-2.0; actively maintained Microsoft repository. Current page showed a same-day commit on 2026-10-22 and the project documents Chromium, Firefox and WebKit automation across Windows/macOS/Linux. | TypeScript/Node-friendly; installed as a MAJIN dev dependency already. Structured locators and browser-level evidence are better than hand-rolled coordinate clicks. Browser binaries add disk/CI cost; real page content remains untrusted. Existing MAJIN DOM verifier degrades honestly when unavailable. | **Adopt for browser verification/E2E**, no new dependency this round. No source vendoring. Test against the installed version and real Windows Edge/Chrome before production claims. |
| [browser-use/browser-use](https://github.com/browser-use/browser-use) | MIT, stated by its repository/FAQ; project activity and releases were visible in the current repository. | High-level AI browser agent with Python and local/hosted modes. Adds a Python runtime, browser-use dependencies and another planning/execution loop; can duplicate MAJIN's Node CDP/grounding/receipts. Hosted service is not the same as OSS. Security review must separate web content from tool authority. | **Defer.** Keep as a candidate specialist adapter if Playwright-grounded V1 browser tools fail a measured objective. No copying. |
| [LiveKit Agents](https://github.com/livekit/agents) | Apache-2.0 framework; repository documents model/plugin ecosystem and realtime voice; some optional model assets have separate terms. | Python server/participant and WebRTC-centric architecture; VAD/STT/LLM/TTS composition and turn-taking are relevant. Adds network/transport/service footprint and cross-runtime Windows packaging. Measure mic interruption/reconnection on the target Windows setup first. | **Research / defer** until voice latency, barge-in and Swedish acceptance are measured; model license terms need separate review. |
| [Pipecat](https://github.com/pipecat-ai/pipecat) | BSD-2-Clause; repository describes Python pipelines for realtime voice and multimodal services. | Strong composable transport/service pipeline and agent fan-out. Additional Python services and provider-specific dependencies are materially heavier than the current local Node app; target Windows support and runtime packaging must be proven before selection. | **Defer**; evaluate against real MAJIN voice traces, not feature lists. |
| [Silero VAD](https://github.com/snakers4/silero-vad) | MIT; current repository documents pretrained VAD, realtime example and portable model ecosystem. | Potential low-footprint VAD for turn detection. Integrating model inference and audio buffers into MAJIN still needs runtime choice (ONNX/PyTorch), Windows packaging, Swedish/noise/interruption evidence and model notice checks. | **Candidate, not integrated.** Benchmark against the existing voice pipeline before adopting. |
| [LangGraph](https://github.com/langchain-ai/langgraph) | MIT repository; active Python/JS project and current release activity visible in GitHub. | Checkpointed graph execution and human-in-loop patterns are relevant, but V2 already has local Goal, DAG, scheduler and recovery. Introducing another state runtime risks duplicate state, cross-language glue and competing persistence. | **Defer** unless objective benchmarks identify a specific V2 gap. Reuse patterns, not code, for now. |
| [OpenHands](https://github.com/OpenHands/OpenHands) | MIT core according to its repository; recent releases visible. | Coding agent/SDK and sandbox patterns are relevant. Official setup guidance says Windows support is through WSL + Docker, a significant install/resource change for MAJIN. Scope individual subdirectory licenses before code reuse. | **Research / defer** as optional isolated coding worker; do not put it on the default Windows runtime path. |
| [Mem0](https://github.com/mem0ai/mem0) | Apache-2.0 repository; current repo lists Python/TypeScript clients and OSS memory options. | Persistent retrieval is relevant, but common self-hosted configurations bring embeddings/LLM calls and vector-store dependencies (for example Qdrant); that is more resource and privacy surface than the existing local V2 store. | **Defer** until retrieval relevance, deletion/export and scale benchmarks show a need. |

## Selection scorecard for the current vertical slice

- **Reuse internal V2 Goal and verifier:** best fit, zero new runtime dependency, already matches the repo's acceptance/receipt contract, locally testable. Selected.
- **Use Playwright for later browser proof:** suitable and already in `devDependencies`; not needed for the current non-browser file task. Selected for verification work, not added or invoked by this task.
- **Do not integrate browser-use, LiveKit, Pipecat, LangGraph, OpenHands or Mem0 yet:** each adds an additional framework/runtime or storage model before a target acceptance gap has been measured. This is an evidence-based defer, not a claim that those projects are inferior.
