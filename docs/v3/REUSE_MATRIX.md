# MAJIN V3 reuse matrix

Decision principle: reuse verified in-repository components first. External source is not copied in this round. The V3 demo is deliberately small and wraps V2 contracts rather than forking its goal, receipt or verification implementations.

| Capability | Existing source | Decision | V3 use / reason | Risk, license and rollback |
|---|---|---|---|---|
| Goal lifecycle | `src/v2/runtime/goal.js`, `states.js` | **ADOPT** | `src/v3/runtime/file-deliverable.js` creates a V2 Goal, follows legal transitions and relies on the verified-acceptance completion gate. | Internal code; no new license obligation. Revert only the V3 adapter if V2 contract changes. |
| Action proof | `src/v2/runtime/receipts.js`, `verifiers.js` | **ADOPT / WRAP** | V3 invokes `runVerifier('file', …)`, validates the computed SHA-256, then marks the action receipt verified. | Existing V2 semantics and dependency set. Keep V2 files unchanged. |
| Goal persistence | `Goal.save()` / `Goal.list()` | **ADOPT** | Checkpoints are written below the explicit workspace at `.majin/v3/goals/`. | Existing atomic-temp/rename behavior; needs crash/restart testing on Windows and concurrent-write testing. |
| Task graph / scheduler | `src/v2/runtime/dag.js`, `scheduler.js` | **ADAPT (next)** | Use when V3 adds real multi-step tasks; no duplicate scheduler is being built. | Must preserve bounded concurrency, cancellation and idempotence. Roll back the V3 integration without changing V2. |
| Existing computer/browser tools | V1 `src/core/browser*.js`, `computer-use.js`, `src/core/tools/*` | **WRAP (next)** | Reuse structured DOM/CDP/accessibility paths behind per-goal permission gates and V2 receipts. | High-impact actions need a V3-specific authorization contract and real Windows/browser evidence first. |
| Existing providers | V1 `src/core/provider/*`; V2 `src/v2/model/*` | **ADAPT (next)** | Preserve the existing provider route and key discipline rather than introducing another SDK family. | Verify model persistence, cancellation and errors before enabling V3 production requests. |
| Existing memory | V1 `src/core/memory.js`; V2 `src/v2/memory/store.js` | **ADAPT / DEFER** | Keep simple local storage and provenance until measured retrieval needs justify more infrastructure. | Existing file store is easier to export/delete; preserve compatibility and privacy. |
| Existing Studio | `src/v2/studio/page.js`, `server.js` | **WRAP advanced / replace default** | V3 gets a separate minimal page. V2 operator Studio is not replaced or modified. | New page is isolated under `src/v3/ui/`; remove that module to roll back. |
| Browser automation framework | [Microsoft Playwright](https://github.com/microsoft/playwright) | **ADOPT for test/verification; already present** | Existing package has Playwright as a dev dependency; use it for future DOM/E2E proof instead of writing a browser harness. No new dependency added in this round. | Apache-2.0; preserve notices if distributing the dependency. The current V3 server test uses native `fetch`; browser-rendered acceptance is still unrun. |
| Browser-use agent framework | [browser-use/browser-use](https://github.com/browser-use/browser-use) | **DEFER** | Useful maintained MIT project, but Python runtime and an additional browser-agent loop duplicate MAJIN's Node/CDP + V2 goal system. Re-evaluate for a specialized browser worker only if current structured tools fail a benchmark. | MIT; no source copied. Integration would add a Python environment, dependencies and another execution boundary. |
| Realtime voice framework | [livekit/agents](https://github.com/livekit/agents), [pipecat-ai/pipecat](https://github.com/pipecat-ai/pipecat) | **RESEARCH / DEFER** | Both are mature Python voice-pipeline candidates. V2 has voice adapters already; first measure real latency/interruption on Windows before adopting a second runtime/transport. | LiveKit Agents Apache-2.0; model assets may have separate terms. Pipecat BSD-2-Clause. Avoid accidental model-license or attribution gaps. |
| VAD | [snakers4/silero-vad](https://github.com/snakers4/silero-vad) | **CANDIDATE (not integrated)** | MIT VAD with published realtime examples and portable model formats; evaluate ONNX/Windows size/latency against microphone hardware before selection. | Model/runtime integration and model-weight notices must be reviewed. No VAD pass is claimed. |
| Agent orchestration | [langchain-ai/langgraph](https://github.com/langchain-ai/langgraph) | **DEFER** | MIT graph/checkpoint framework is credible, but MAJIN already has a goal state machine, DAG, scheduler, receipts and recovery. Replacing them now would create duplicate abstractions and a cross-language integration burden. | No code copied. Revisit only if a benchmark shows a concrete gap in V2's DAG/recovery. |
| Coding agent / sandbox | [OpenHands/OpenHands](https://github.com/OpenHands/OpenHands) | **RESEARCH / DEFER** | MIT core is an option for isolated coding workers, but the documented Windows path uses WSL/Docker and adds a substantial runtime. MAJIN must preserve a simple Windows-first install. | Check the exact release's repository and subdirectory licenses before embedding; no code copied. |
| Memory platform | [mem0ai/mem0](https://github.com/mem0ai/mem0) | **DEFER** | Apache-2.0 memory tooling offers durable retrieval, but its common self-hosted path adds an embedding/LLM layer and vector-store dependencies. Current local file memory is simpler and easier to export/delete. | No new infrastructure until relevance, deletion, privacy and scale benchmarks justify it. |

## Decisions this round

- **No new production or development dependencies.**
- **Reused internal V2 code:** durable Goal/state/receipt model and independent V2 file verifier.
- **Reused standard library:** `node:fs`, `node:path`, `node:crypto`, `node:http`, browser `fetch`.
- **New code is an adapter and a preview UI, not copied upstream source.**
- V3 runtime-floor work is a separate compatibility change touching package/lock metadata, shared installer/startup surfaces, the V2 Doctor's Node check, V3 runtime/tests/CI and evidence docs. Revert only its dedicated commit on `v3/main` if necessary; never move or reset protected refs. V2 Goal/verifier implementations remain unchanged.
